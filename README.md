# Replay Lab

K리그 영상에서 관측한 정보와 적용 규정을 연결하는 판정 보조 프로젝트

> 현재는 영상 처리·관측·비공개 저장·규정 평가 기반을 구현한 개발 단계다
> 실제 영상의 잡기·접촉·이동 방해를 검증된 사실로 생산하는 방법은 아직 없으며 자동 파울 판정 서비스가 완성된 상태는 아니다

문서 기준: 2026-09-26 작업 폴더의 코드 · 구현 상태와 배포 상태는 별도

## 1 어떤 프로젝트인가

사용자는 분석 권한이 있는 영상 파일을 업로드하고 서버가 제공하는 결과를 열람한다
대회·시즌·임계값·선수 좌표·관측 사실을 사용자에게 설정하거나 확인하게 하지 않는다

목표 흐름은 다음과 같다

```text
영상 → 검출·추적·포즈·음향 관측 → 사건 연결
     → 검증된 사실에 규정 적용 → 완료된 질문의 근거와 결과 공개
```

장면 후보와 행위 유형과 반칙 성립은 서로 다르다
손목이 몸통 가까이에 있다는 측정만으로 잡기를 확정하지 않고 움직임 변화만으로 인과적 이동 방해를 확정하지 않는다
판정 보조 의견은 공식 심판 판정이나 오심 확정이 아니다

## 2 계획

두 개발 흐름을 병행하고 사실별 승인 단계에서 합류한다

| 흐름 | 진행 순서 | 검증 기준 |
|---|---|---|
| 연결·저장 | 관측·사건 수신 → 비공개 저장·재조회 → 승인 검사 → 규정 평가 → 질문별 저장·공개 필터 | 계약·출처·권한·판본·만료·트랜잭션 유지 |
| 인식·검증 | 평가 자료 준비 → 유형·방향·접촉·이동 방해 생산 → 사실별 성능 검증 | 독립 실영상에서 오탐·누락·미확인과 근거 검증 |

합성 자료로 연결 시험을 통과한 것과 실제 영상 사실의 신뢰성 승인은 구분한다
승인은 사건 전체가 아니라 방법·사실·증거 단위로 적용한다
현재 운영 승인 목록은 비어 있으며 개발용 검증 보고서는 자동 승인하지 않는다

## 3 구현한 것

| 영역 | 현재 코드에 있는 기능 | 의미하지 않는 것 |
|---|---|---|
| 업로드·작업 처리 | 익명 세션 소유권·업로드 검증·멱등성·임대와 heartbeat·결과 저장 | 배포 환경과 부하 검증 완료 |
| Worker | 검증용·분석용 실행 분리·샷·후보·프레임·클립 생성 | 모든 리플레이와 반칙 자동 인식 |
| 영상 관측 | 승인된 RT-DETR·YOLO11m·ViTPose 및 추적 출력 활용 | 선수 신원·팀·실제 접촉 확정 |
| 음향 | 기존 DSP 관측·소리 포함 클립·시간 연결·디코딩 오류 검사 | 발화 전사·화자 식별·음향 의미 판정 |
| 상호작용 | 중립 참여자 쌍·구간별 화면 거리·속도·관절 각도·미확인 사유 보존 | 실제 충격력이나 접촉 인과 측정 |
| 사건 연결 | 독립 유형·방향 가설을 받는 사건 변환기·비공개 DB 색인·인증된 내부 조회 | 실제 잡기 유형·방향 생산자 구현 |
| 규정 | 기존 밀기 엔진·VAR 범주 분석·독립 잡기 성립 및 제한된 재개 평가 | 전체 반칙·징계·원심 비교·VAR 개입 자동 판정 |
| 승인·공개 경계 | 기본 거부 사실 승인·질문별 평가 저장·완료 질문만 추리는 순수 투영 | 새 잡기 결과의 공개 API·프론트 연결 |
| 개발 검증 | 사실별 라벨 계약·분할 누수와 중복 검사·지표 도구·실영상 산출물 감사 | 독립 잡기 라벨 확보와 인식 성능 검증 완료 |

기존 공개 경로는 완료된 규정 평가만 표시한다
등록된 원본의 득점 관련 방송 단서와 검증된 대회요강을 연결하는 VAR 적용 범주 결과는 전체 파울 판단과 별개다
평가 결과가 없다는 것은 파울이 없다는 뜻이 아니다

이전 실영상 산출물 재처리에서는 관측 2,154개와 측정값 26,328개를 보존했지만 유형별 사건과 승인 사실은 0건이었다
이는 모델 재추론이나 실제 반칙 정확도 시험이 아니라 기존 산출물의 재처리 기록이다

## 4 구현해야 하는 것

1. 잡기 유형·행위 방향·접촉·잡기 유지·당김·인과적 이동 방해의 생산 방법 개발
2. 독립적인 실영상 평가 자료 확보와 사실별 성능 검증
3. 검증 보고서와 적용 범위에 근거한 운영 사실 생산자 승인
4. 새 잡기 평가의 질문별 결과를 공개 API·프론트에 연결하고 공개 직전 유효성 재검사
5. 징계·위험성·원심 비교·VAR 및 다른 반칙 유형의 별도 평가 구현과 검증
6. 배포 환경에서 마이그레이션·역할별 Worker·보존 정책·자원 사용·장애 복구 검증

새 모델과 추가 학습은 별도 설계 승인 없이 도입하지 않는다
새 잡기 공개 연결은 시험 자료로 개발할 수 있지만 실제 판정 활성화에는 검증된 사실이 필요하다

## 로컬 실행과 검증

Node.js 22 이상·npm·Docker·FFmpeg·ffprobe가 필요하다
Python 시험 환경은 CI의 3.11.9와 고정 의존성을 기준으로 준비한다

1. `npm ci`로 웹 의존성 설치
2. [.env.example](.env.example)을 참고해 `apps/web/.env.local` 준비 — 기존 설정을 덮어쓰지 않음
3. `npm run dev:infra` 실행 후 MinIO에 `STORAGE_BUCKET`에 지정한 비공개 버킷 준비
4. 로컬 대상의 `DATABASE_URL`을 셸에도 설정하고 `npm run db:migrate` 실행
5. [Worker 실행 안내](apps/video-worker/README.md#사이트-연결-worker-실행)에 따라 전용 환경과 승인 모델 자산 준비
6. 아래 명령을 각각 별도 터미널에서 실행

```sh
npm run dev:web
npm run dev:worker:validate
npm run dev:worker:analyze
```

접속 주소: http://localhost:3100/analyze
기존 혼합 Worker는 활성 작업 종료 후 중단하고 두 역할로 전환한다
최신 비공개 사건 저장 코드에는 `0021_private_incidents` 적용이 필요하다
마이그레이션 파일 존재만으로 운영 DB 적용이나 서비스 전환이 완료된 것은 아니다

[공통 시험 환경](apps/video-worker/README.md#ci와-같은-시험-환경)을 준비하고 `TEST_PYTHON`을 절대 실행기 경로로 지정한다

```sh
npm run check
npm run test:video
npm run test:perception
```

마지막 명령에는 별도 인식 실증 환경이 필요하다
DB 통합 시험에는 전용 테스트 DB와 마이그레이션이 필요하고 실매체·객체 저장소 시험은 입력 조건이 갖춰져야 실행된다
시험 통과와 제외 항목 및 실제 영상의 의미 정확도를 구분해 보고한다
