# Replay Lab

K리그 판정 장면을 영상 증거와 경기 규정 및 공식 결론에 연결해 검토하는 판정 근거 시스템

> 현재 상태 (2026.11 기준)
> 영상 분석과 규정 평가 파이프라인은 코드 연결까지 구현했으며 실영상 정확도는 검증 전입니다
> 공식 결론이 나온 판정 장면을 모아 비교하는 판정 일관성 아카이브를 같은 저장소에 붙여 진행하고 있습니다
> 이 프로젝트는 오심을 확정하거나 심판 개인을 평가하지 않습니다

## 1 문제 정의

### 배경

K리그 판정 논란은 시즌마다 반복되고 있으며 논란이 생기면 영상을 반복해서 재생하고 화면에서 확인한 내용을 규정의 조건과 하나씩 비교하는 수작업 검토가 이어집니다
이 검토 결과는 브리핑과 보도에 흩어져 남아 같은 유형의 장면을 모아 비교하기 어렵습니다

### 확인된 문제

| 문제 | 내용 |
|---|---|
| 판정 일관성 | K리그1·2 감독 29명 중 27명(93.1%)이 아쉬운 점으로 '일관성 없는 판정'을 선택했고 잘못된 판정을 꼽은 감독은 5명이었습니다 |
| 오심 판정 경기 증가 | 협회 제출 자료 기준 오심으로 판정된 경기는 2024년 23경기에서 2025년 56경기로 늘었고 2026년은 8월까지 23경기입니다 |
| 근거 접근성 | 협회는 브리핑에서 오심 여부를 공개하겠다고 밝혔으나 VAR 교신 내용은 공개하지 않는 방침입니다 |
| 검토 비용 | 장면 탐색과 규정 대조를 사람이 반복해서 수행해야 합니다 |

### 해결하려는 문제

> 같은 유형의 장면에 같은 기준이 적용됐는지 확인할 근거 자료가 체계적으로 정리돼 있지 않다

### 범위의 한계

- 오심 여부의 최종 판단은 대한축구협회 심판평가협의체의 결론을 따르며 이 시스템이 새로 확정하지 않습니다
- 영상에서 측정한 값은 관측으로 저장하고 접촉과 반칙 성립은 별도의 사실 검증과 규정 평가 단계에서 다룹니다
- 확인되지 않은 사실은 미확인으로 두며 파울 없음이나 카드 없음으로 바꾸지 않습니다

## 2 솔루션 개요

### 핵심 아이디어

판정 장면을 중심으로 영상 증거와 적용 규정 및 공식 결론을 하나의 기록으로 연결합니다

```text
장면 (원본 영상의 시각)
  ├─ 증거 ─ 프레임 · 클립 · 객체·자세 관측 · 음향 관측
  ├─ 규정 ─ IFAB 경기규칙 판본 · K리그 대회요강 판본
  └─ 결론 ─ 협회 심판평가협의체의 공식 결론 (판례)
```

### 두 개의 축

| 축 | 목적 | 상태 |
|---|---|---|
| 영상 검토 파이프라인 | 업로드한 영상에서 검토할 장면을 찾고 증거를 추출해 규정과 연결 | 코드 연결 구현 · 실영상 정확도 검증 전 |
| 판정 일관성 아카이브 | 공식 결론이 나온 장면을 유형과 규정 조항별로 모아 비교 | 판례 수집과 저장소 연결 진행 중 |

### 현재 진행 방향

- 영상에서 반칙을 자동으로 판별하는 기능은 실영상 검증 자료가 아직 없으므로 공개 판정에 연결하지 않고 관측과 증거 정리 단계에 둡니다
- 공식 결론이 있는 장면을 기준 자료로 삼는 아카이브를 먼저 완성해 영상 분석 결과를 나중에 비교할 기준을 만듭니다
- 영상 분석은 판례와 같은 형식으로 장면을 정리하는 입력 도구로 연결합니다

### 설계 원칙

- 측정과 판정을 분리합니다 화면 좌표 측정은 접촉이나 반칙 성립의 근거로 자동 승인하지 않습니다
- 완료된 규정 평가만 공개합니다 원시 관측과 미완료 질문은 공개 판정으로 바꾸지 않습니다
- 비공개 기본값을 유지합니다 업로드 영상과 증거는 세션에 연결하고 보존 기한 뒤 삭제합니다
- 성능 수치는 합성 영상과 실제 영상을 합치지 않고 따로 보고합니다

### 기술 아키텍처

Next.js가 웹 화면과 API 및 규정 엔진을 담당하고 Python Worker가 영상·음향 연산을 수행합니다
PostgreSQL은 작업 상태와 관측·평가 이력을 관리하며 S3 호환 객체 저장소는 원본과 증거 파일을 보관합니다

```text
사용자
  │ 영상 업로드 · 진행 상태 · 결과 조회
  ▼
Next.js 웹 애플리케이션
  ├─ React 화면
  ├─ 업로드 · 상태 · 결과 API
  ├─ 규정 엔진 · 결과 공개 정책
  ├─ PostgreSQL · 작업 큐와 분석 이력
  └─ S3 호환 저장소 · 원본과 증거
  ▲
  │ 작업 선점 · 진행 보고 · 결과 제출
  │
Python Worker ─────────────── S3 호환 저장소
  ├─ 검증 · ffprobe            원본 읽기 · 증거 저장
  └─ 분석 · OpenCV · FFmpeg · 객체 검출 · 자세 추정 · DSP
```

## 3 주요 기능 정의

### 기능별 현황

상태 표기는 구현 완료는 구현 · 일부만 연결은 부분 · 작업 중은 진행 · 계획만 있는 것은 예정입니다
구현은 코드 연결과 테스트 구성을 뜻하며 실영상 정확도 검증 완료를 뜻하지 않습니다

| 번호 | 기능 | 설명 | 상태 |
|---|---|---|---|
| 1 | 영상 업로드와 분석 작업 관리 | 형식과 메타데이터 검사 후 작업 큐에 등록하고 처리 단계를 조회 | 구현 |
| 2 | 장면 탐색과 증거 추출 | 샷 경계와 움직임 변화로 후보 구간을 찾고 증거 프레임과 클립을 생성 | 구현 |
| 3 | 객체·자세와 움직임 관측 | 사람과 공 검출 및 추적 자세 추정으로 거리와 이동량과 관절 각도를 측정 | 부분 |
| 4 | 영상·음향 시간 연결 | 휘슬 유사 주파수 패턴을 영상과 같은 시간축에 기록하고 음향 포함 클립을 생성 | 구현 |
| 5 | 경기 규정 평가 | 규정 판본을 연결하고 확인된 사실을 질문별 조건과 대조 | 부분 |
| 6 | 근거 중심 결과 조회 | 완료된 평가를 증거 클립과 적용 조항에 연결해 표시 | 구현 |
| 7 | 판정 일관성 아카이브 | 공식 결론이 있는 장면을 유형과 조항별로 수집하고 비교 | 진행 |

### 1 영상 업로드와 분석 작업 관리

- 업로드 요청과 분석 상태 조회 API
- ffprobe 기반 영상 메타데이터 검사
- PostgreSQL 작업 큐와 중복 요청 처리 및 임대 만료 재선점
- 검증 Worker와 분석 Worker의 분리 실행
- 세션 소유권 검사와 비공개 객체 저장소 접근 제어

### 2 장면 탐색과 증거 추출

- OpenCV 기반 샷 경계와 화면 변화 탐색
- 코너 기하와 공 후보 움직임을 이용한 코너킥 영상 패턴 관측
- GOAL 방송 표시의 형태와 지속 시간 검사
- FFmpeg 기반 증거 프레임과 전후 클립 생성
- 원본 해시와 실측 PTS를 이용한 증거 연결

### 3 객체·자세와 움직임 관측

- RT-DETR과 YOLO11m 객체 검출 및 ViTPose 자세 추정
- 추적 ID와 시간 구간을 이용한 참여자 쌍 연결
- 손목과 상대 몸통 사이 거리 및 팔꿈치 각도와 전후 이동량 계산
- 포즈가 없거나 점수가 낮은 측정은 미확인으로 보존

현재 잡기와 접촉 및 이동 방해를 실제 영상에서 판별하는 방법은 없습니다
측정값은 저장하되 규정 사실로 승인하지 않습니다

### 4 영상·음향 시간 연결

- 고정 DSP 기반 주파수 전력과 엔트로피 및 복수 피크 분석
- 원본 PTS를 기준으로 한 영상과 음향의 시간 대응
- 오디오 유무와 디코딩 상태 및 처리 구간 기록

### 5 경기 규정 평가

| 평가 항목 | 적용 범위 | 상태 |
|---|---|---|
| VAR 적용 범주 | 등록된 원본의 득점 관련 방송 단서와 검증된 대회요강 대조 | 공개 결과 연결 |
| 밀기 평가 | 승인된 사실을 입력으로 받는 평가 엔진과 평가 상태 저장 | 평가기만 구현 |
| 잡기 평가 | 승인된 유형·방향·접촉 등의 사실에 따른 반칙 성립과 제한된 경기 재개 평가 | 평가기만 구현 |

평가기가 있다는 것과 관측 방법이 승인됐다는 것은 별개이며 현재 운영 사실 생산자 목록은 비어 있습니다

### 6 근거 중심 결과 조회

- 완료된 규정 평가만 선택하는 공개 정책
- 장면 시각과 클립 및 적용 조항을 함께 표시
- 영상 구간 요청을 지원하는 증거 파일 전달

### 7 판정 일관성 아카이브

수집 항목(안)

| 항목 | 내용 |
|---|---|
| 경기 정보 | 대회 라운드 경기 일시 |
| 장면 | 경기 시각과 장면 설명 |
| 판정 유형 | 핸드볼 푸싱 PK 득점 취소 등 |
| 적용 규정 | IFAB 경기규칙과 K리그 대회요강의 판본과 조항 |
| 현장 판정과 VAR | 주심의 현장 판정과 VAR 개입 여부 |
| 공식 결론 | 협회 심판평가협의체의 결론과 발표일 |
| 출처 | 결론이 실린 공식 발표 또는 보도 링크 |
| 유사 장면 | 같은 유형과 조항의 다른 판례 연결 |

### 앞으로 해야 할 부분

우선순위 순서입니다

1. 판정 일관성 아카이브
   - 수집 항목과 판정 유형 분류 확정
   - K리그 판례 수집과 저장소 연결 완료
   - 유형과 조항별 비교 화면 구현
2. 영상 분석과 아카이브 연결
   - 분석 결과의 후보 장면을 판례와 같은 항목으로 정리
   - 같은 유형의 판례를 장면 옆에 함께 표시
3. 실영상 정확도 검증
   - 경기 단위로 개발과 평가 분할을 나눈 정답 라벨 구축
   - 코너킥 외 세트피스와 잡기 사실의 정밀도 재현율 미확인 비율 보고
   - 검증 통과 전에는 자동 평가와 공개 판정에 연결하지 않음
4. 공개 서비스 전 점검
   - 모델 라이선스 검토 (YOLO11m의 AGPL-3.0 조건 포함)
   - 저장소 라이선스 명시
   - 경기 영상의 사용 권한과 보관 방식 검토
5. 후속 개발 항목
   - 잡기 결과의 공개 API와 화면 연결
   - 실제 주심 판정과의 비교와 VAR 개입 평가

### 기술

| 영역 | 기술 | 용도 |
|---|---|---|
| 웹 프레임워크 | Next.js 16 · React 19 | 업로드·분석 진행·결과 화면과 API |
| 언어 | TypeScript · Python | 웹·규정 엔진과 영상 Worker |
| 영상 처리 | FFmpeg · ffprobe · OpenCV | 미디어 검증·장면 탐색·증거 추출 |
| 객체·자세 관측 | RT-DETR · YOLO11m · ViTPose | 검출 상자와 관절 좌표 관측 |
| 음향 처리 | 고정 DSP | 휘슬 유사 주파수 관측과 시간 연결 |
| 데이터베이스 | PostgreSQL · Drizzle ORM | 작업 큐·관측·평가 이력 저장 |
| 객체 저장소 | S3 호환 저장소 · MinIO | 원본 영상과 증거 파일 보관 |
| 테스트 | Vitest · Testing Library · pytest | 웹·규정 엔진·Worker 검증 |

### 검증 방법

- 정답 파일과 방법 예측 파일을 따로 받아 결합해 사실 단위 지표를 계산합니다
- 개발과 평가를 경기 단위로 나누고 같은 사건의 리플레이가 서로 다른 분할에 들어가지 않게 합니다
- 정밀도와 재현율과 미확인 비율을 함께 보고하며 합성 영상 결과는 실제 영상 성능과 합치지 않습니다
- 지표 계산이 끝나도 운영 승인으로 이어지지 않으며 승인은 별도 단계입니다

### 데이터 사용상의 전제

- 원본 영상은 저장소에 포함하지 않고 비공개 저장소에서 TTL 후 삭제합니다
- 원본 영상의 사용 권한은 모델 라이선스와 별개이며 공개 서비스 전에 검토합니다
- 공식 결론은 출처 링크와 함께 기록하며 원문을 그대로 복제하지 않습니다

## 5 시나리오

### 시나리오 1 영상에서 검토 장면을 찾는 경우 (구현된 흐름)

1. 사용자가 K리그 하이라이트 영상을 업로드합니다
2. 시스템이 형식을 검증하고 분석 작업을 등록합니다
3. Worker가 후보 구간을 찾고 증거 프레임과 전후 클립을 추출합니다
4. 득점 관련 방송 단서가 있으면 대회요강의 VAR 적용 범주와 대조합니다
5. 사용자가 결과 화면에서 장면 시각과 클립과 적용 조항을 함께 확인합니다
6. 접촉이나 반칙처럼 검증되지 않은 사실은 미확인으로 표시됩니다

### 시나리오 2 판례를 비교하는 경우 (진행 중인 방향)

예시로 2026년 8월 1일 K리그2 20라운드 충북청주 대 수원 경기를 보면 협회는 8월 4일 브리핑에서 세 가지 논란 장면을 나눠 결론을 냈습니다
팔 가격 장면은 오심으로 인정했고 핸드볼 논란은 핸드볼이 아니라고 했으며 막판 득점 취소는 푸싱 파울로 정심이라고 설명했습니다

1. 사용자가 판정 유형(예 팔 사용 반칙 득점 취소)으로 판례를 검색합니다
2. 시스템이 같은 유형과 조항의 판례를 시즌과 경기 순으로 나열합니다
3. 각 판례에 현장 판정과 VAR 개입 여부와 공식 결론과 출처가 함께 표시됩니다
4. 사용자는 비슷한 장면에서 결론이 어떻게 달랐는지 한눈에 비교합니다
5. 영상 분석 결과가 있으면 같은 유형의 판례를 장면 옆에 함께 확인합니다

### 예상 사용자 (수요 검증 전)

- 구단 분석팀 판정 이의 제기와 경기 복기 자료 준비
- 스포츠 미디어와 판정 해설 제작자 판정 해설의 근거 자료 확인
- 심판 교육 담당 유형별 판정 사례 학습

## 6 기대 효과 및 추후 확장성

| 기대효과 | 내용 |

| 검토 시간 단축 | 후보 장면과 전후 클립과 관련 조항을 따로 찾는 수고 감소 |

| 분석 품질 개선 | 관측과 평가 이력을 비교해 오류 원인과 보완 대상 파악 |

|---|---|

| 중기 | 실영상 정답 라벨 구축과 정확도 보고 · 코너킥 외 세트피스와 잡기 사실 검증 · 잡기 결과 공개 API |
| 장기 | 주심 판정과 비교 · VAR 개입 평가 · 시즌별 유형별 일관성 지표 · 다른 리그와 다른 종목으로 확장 |

### 한계와 검증이 필요한 가정

- 실영상에서 반칙 사실을 판별하는 정확도는 아직 측정되지 않았습니다
- 판례 비교 서비스에 대한 실제 사용자 수요와 지불 의사는 확인 중에 있습니다
- 경기 영상의 사용 권한과 모델 라이선스는 공개 서비스 전에 해결해야 합니다
- 공식 결론의 공개 범위와 형식은 협회의 정책에 따라 달라질 수 있습니다
