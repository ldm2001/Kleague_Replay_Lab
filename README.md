# Replay Lab

경기 영상과 규정을 연결하는 K리그 판정 보조 시스템

## 1 제안 배경 및 목적

### 프로젝트 개요

Replay Lab은 K리그 경기 영상과 경기 규정을 함께 검토하기 위한 판정 보조 시스템입니다
영상에서 검토할 장면을 찾고 증거 프레임과 클립을 추출해 해당 경기의 규정과 연결하는 것을 목표로 합니다

사용자는 경기 영상을 업로드하고 분석 진행 상황과 평가가 완료된 결과를 확인합니다
영상 처리와 관측은 Python Worker가 담당하고 규정 평가는 웹 서버의 규정 엔진이 수행합니다

### 제안 배경

축구 경기의 판정을 검토하려면 영상에서 해당 장면을 찾고 전후 상황을 살핀 뒤 관련 규정을 대조해야 합니다
이 과정에서 영상을 반복해서 재생하고 화면에서 확인한 내용을 규정의 조건과 비교하게 됩니다

Replay Lab은 검토할 장면과 관련 규정을 따로 찾는 수고를 줄이기 위해 제안한 프로젝트입니다
장면별 영상 증거와 적용 조항을 함께 정리해 판정 근거를 확인할 수 있도록 합니다

### 제안 목적

- 장면 탐색 — 경기 영상에서 검토할 구간과 전후 맥락 추출
- 증거 정리 — 원본 시각에 맞춘 프레임·클립·영상 및 음향 관측 연결
- 규정 대조 — 경기 정보에 맞는 규정 판본과 확인된 사실 비교
- 근거 설명 — 평가 결과와 적용 조항 및 증거를 함께 확인하는 화면 구성

## 2 제안 범위

### 핵심 기능

#### 1 영상 업로드와 분석 작업 관리

사용자가 업로드한 영상의 형식과 메타데이터를 확인하고 분석 작업을 등록합니다
웹 화면에서 처리 단계를 조회하며 원본 영상과 분석 결과는 업로드한 사용자의 세션에 연결합니다

구현 기술

- Next.js API를 통한 업로드 요청과 분석 상태 조회
- ffprobe 기반 영상 메타데이터 검사
- PostgreSQL 작업 큐와 중복 요청 처리
- 검증 Worker와 분석 Worker의 분리 실행
- 세션 소유권 검사와 비공개 객체 저장소 접근 제어

#### 2 장면 탐색과 증거 추출

화면 전환과 움직임 변화를 분석해 검토할 후보 구간을 찾습니다
후보 장면의 프레임과 전후 상황이 포함된 짧은 클립을 추출하고 원본 영상의 시각과 연결합니다

구현 기술

- OpenCV 기반 샷 경계와 화면 변화 탐색
- 코너 기하와 공 후보 움직임을 이용한 코너킥 영상 패턴 관측
- GOAL 방송 표시의 형태와 지속 시간 검사
- FFmpeg 기반 증거 프레임과 클립 생성
- 원본 해시와 타임스탬프를 이용한 증거 연결

생성 자료

- 후보 구간의 시작·종료 시각
- 장면별 증거 프레임과 전후 클립
- 영상 패턴과 방송 표시의 관측 기록

#### 3 객체·자세와 움직임 관측

RT-DETR·YOLO11m·ViTPose의 검출 및 자세 추정 결과와 추적 정보를 이용해 화면 속 위치와 움직임을 기록합니다
같은 장면의 참여자 쌍을 연결하고 손목과 상대 몸통 사이 거리 및 전후 이동량을 화면 좌표 기준으로 측정합니다

구현 기술

- RT-DETR·YOLO11m 객체 검출과 ViTPose 자세 추정
- 추적 ID와 시간 구간을 이용한 참여자 쌍 연결
- 검출 상자와 관절 좌표를 이용한 거리·각도·이동량 계산
- 측정값과 원본 프레임 및 증거 클립의 연결

관측 항목

- 참여자 사이의 화면상 거리와 이동 변화
- 손목 위치와 팔꿈치 각도
- 추적 연속성과 측정 가능한 구간

화면 좌표 측정은 영상 관측으로 저장하고 접촉과 반칙 성립은 사실 검증과 규정 평가 단계에서 별도로 다룹니다

#### 4 영상·음향 시간 연결

원본 영상의 음향에서 휘슬과 유사한 주파수 패턴을 관측하고 영상 후보와 같은 시간축에 기록합니다
증거 클립에는 원본에서 가져온 소리를 함께 담고 영상과 음향의 시작 시각을 맞춥니다

구현 기술

- 고정 DSP 기반 주파수 전력과 엔트로피 및 복수 피크 분석
- 원본 PTS를 기준으로 한 영상·음향 시간 대응
- FFmpeg 기반 음향 포함 클립 생성
- 오디오 유무와 디코딩 상태 및 처리 구간 기록

음향 관측과 시간 대응 자료는 장면의 맥락을 검토하는 비공개 분석 자료로 보존합니다

#### 5 경기 규정 평가

규정 엔진은 검증된 경기 정보와 규정 판본을 연결하고 확인된 사실을 질문별 조건과 대조합니다
반칙 성립과 경기 재개 및 VAR 적용 범주를 구분해 평가 결과와 적용 근거를 기록합니다

구현 기술

- TypeScript 기반 순수 규정 평가 함수
- 경기 정보에 따른 규정 판본 연결
- 사실별 출처와 증거 및 사용 가능 여부 검사
- 평가 결과와 적용 조항 및 근거 참조 저장

구현 범위

| 평가 항목 | 적용 범위 |
|---|---|
| VAR 적용 범주 | 등록된 원본의 득점 관련 방송 단서와 검증된 대회요강 대조 |
| 밀기 평가 | 승인된 사실을 입력으로 받는 평가 엔진과 평가 상태 저장 |
| 잡기 평가 | 승인된 유형·방향·접촉 등의 사실에 따른 반칙 성립과 제한된 경기 재개 평가 |

실영상에서 잡기·접촉·이동 방해를 판별하는 방법의 개발과 독립 영상 검증을 거쳐 자동 평가에 연결할 계획입니다
잡기 결과의 공개 API와 화면 연결 및 징계·실제 주심 판정 비교·VAR 개입 평가는 후속 개발 항목입니다

#### 6 근거 중심 결과 조회

규정 평가가 완료된 결과를 증거 영상과 적용 조항에 연결해 보여줍니다
사용자는 결과 화면에서 장면의 시각과 클립 및 판단 근거를 함께 확인합니다

구현 기술

- React 기반 분석 진행 화면과 결과 화면
- 완료된 규정 평가만 선택하는 공개 정책
- 세션 소유권과 증거 유효성 검사
- 영상 구간 요청을 지원하는 증거 파일 전달

### 기술 아키텍처

Next.js가 웹 화면과 API 및 규정 엔진을 담당하고 Python Worker가 영상·음향 연산을 수행합니다
PostgreSQL은 작업 상태와 관측·평가 이력을 관리하며 S3 호환 객체 저장소는 원본과 증거 파일을 보관합니다

```text
사용자
  │ 영상 업로드 · 진행 상태 · 결과 조회
  ▼
Next.js 웹 애플리케이션
  ├─ React 화면
  ├─ 업로드 · 상태 · 결과 API
  ├─ 규정 엔진 · 결과 공개 정책
  ├─ PostgreSQL · 작업 큐와 분석 이력
  └─ S3 호환 저장소 · 원본과 증거
  ▲
  │ 작업 선점 · 진행 보고 · 결과 제출
  │
Python Worker ─────────────── S3 호환 저장소
  ├─ 검증 · ffprobe            원본 읽기 · 증거 저장
  └─ 분석 · OpenCV · FFmpeg · 객체 검출 · 자세 추정 · DSP
```

### 기술 스택

| 영역 | 기술 | 용도 |
|---|---|---|
| 웹 프레임워크 | Next.js 16 · React 19 | 업로드·분석 진행·결과 화면과 API |
| 언어 | TypeScript · Python | 웹·규정 엔진과 영상 Worker |
| 영상 처리 | FFmpeg · ffprobe · OpenCV | 미디어 검증·장면 탐색·증거 추출 |
| 객체·자세 관측 | RT-DETR · YOLO11m · ViTPose | 검출 상자와 관절 좌표 관측 |
| 음향 처리 | 고정 DSP | 휘슬 유사 주파수 관측과 시간 연결 |
| 데이터베이스 | PostgreSQL · Drizzle ORM | 작업 큐·관측·평가 이력 저장 |
| 객체 저장소 | S3 호환 저장소 · MinIO | 원본 영상과 증거 파일 보관 |
| 테스트 | Vitest · Testing Library · pytest | 웹·규정 엔진·Worker 검증 |

### 실행 방법

#### 환경 준비

Node.js 22 이상과 Python 3.11 및 FFmpeg·ffprobe를 준비합니다
로컬 PostgreSQL과 MinIO 실행에는 Docker를 사용합니다
모든 명령은 저장소 루트에서 실행합니다

```sh
npm ci
npm run dev:infra
```

[환경변수 예시](.env.example)를 참고해 `apps/web/.env.local`을 작성합니다
PostgreSQL 연결과 비공개 저장소 버킷 및 Worker 인증 정보를 설정합니다
기존 환경 파일이 있다면 필요한 항목만 갱신합니다

`DATABASE_URL`을 명령 실행 환경에 설정하고 연결 대상 DB를 확인한 뒤 마이그레이션을 적용합니다
현재 비공개 사건 저장에는 `0021_private_incidents`까지의 마이그레이션이 필요합니다

```sh
npm run db:migrate
```

분석 Worker의 Python 환경과 모델 자산은 [Worker 실행 안내](apps/video-worker/README.md#사이트-연결-worker-실행)에 따라 준비합니다

#### 서버 실행

각 명령은 별도 터미널에서 실행합니다

```sh
# 웹 서버
npm run dev:web

# 영상 검증 Worker
npm run dev:worker:validate

# 영상 분석 Worker
npm run dev:worker:analyze
```

접속 주소는 http://localhost:3100/analyze 입니다
기존 혼합 Worker를 사용하고 있다면 활성 작업을 마친 뒤 종료하고 두 Worker를 실행합니다

#### 테스트

[Worker 시험 환경](apps/video-worker/README.md#ci와-같은-시험-환경)을 준비하고 `TEST_PYTHON`을 설정한 뒤 실행합니다

```sh
# 타입과 규정 자료 검사 · 웹 테스트
npm run check

# 영상 Worker 테스트
npm run test:video
```

인식 실증 환경을 준비한 경우 `npm run test:perception`으로 관측 모델 연동 테스트를 실행합니다
