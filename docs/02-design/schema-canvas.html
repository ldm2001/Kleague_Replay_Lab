Replay Lab 스키마

판정 결과를 결론이 아니라 이유로 저장하는 데이터 모델. 네 게이트를 각각 다른 열에 두고, 사실값과 규정 판본과 엔진 버전을 함께 남겨 같은 입력이 같은 결과를 재현하게 한다.

확정한 어휘 일곱

README 13절이 “픽스처에 쓰인 모든 대문자 값은 8절에 정의”라고 못박으므로 8절이 어휘의 소유자다. 채택은 8절을 그대로 따른 것, 확장은 8절 어휘로 원문을 표현할 수 없어 넓힌 것 — 넓힌 근거는 전부 IFAB 원문의 쪽수까지 적었다.

error_magnitude

채택
확정
CLEAR_AND_OBVIOUS · NOT_CLEAR_AND_OBVIOUS · UNDETERMINED
폐기
SERIOUS_MISSED_INCIDENT · MARGINAL

원문은 “clear and obvious error or serious missed incident”로 둘을 나란히 놓는다. 정도 축에 섞으면 “놓친 사건”이 “덜 명백한 오심”으로 읽힌다.

대신 VarFacts.seriousMissedIncident: boolean을 별도 입력으로 둔다. 문턱 게이트가 두 입력을 OR로 읽으므로, 오심 정도가 UNDETERMINED여도 미인지가 확인되면 문턱은 넘는다.

review_scenario

채택
확정
8절 9값 그대로. VAR_INCIDENT_TYPES → REVIEW_SCENARIOS
흡수
THROW_IN · OFFSIDE_POSITION → OTHER

OTHER를 되살린 것이 핵심이다. 8절 1037행이 이 값을 OUT_OF_SCOPE로 가는 입구라고 명시한다 — 빼면 “규정이 다루지 않는다”고 답할 경로가 사라진다. 오프사이드는 단독 범주가 아니라 득점 검토 안에서 확인되고, 절차는 decision_nature: FACTUAL이 이미 가른다.

파급 PENALTY_NOT_AWARDED→PENALTY_NOT_GIVEN, CORNER_AWARDED→CORNER_KICK_AWARDED, DIRECT_SEND_OFF→CARD_SHOWN+SENDING_OFF_NOT_GIVEN (원문 범주가 양방향을 다 덮는다).

camera_sufficiency

채택
확정
LOW · MEDIUM · HIGH
폐기
"low" · "medium" · "high" (11절 1690행)

README가 두 절에서 다르게 적은 것이라 어느 쪽이든 README를 고쳐야 했다. 대문자로 간 이유는 13절이 대문자를 기준으로 검사 규칙을 세웠기 때문이다 — 소문자 하나를 남기면 check/enums.mjs가 영구적으로 예외를 하나 갖는다.

남은 소문자 DISPLACEMENT_LEVELS(none·possible·clear·uncertain)와 OBSERVED_SEVERITIES의 uncertain은 그대로 둔다. 8절의 저장 열이 아니라 엔진 내부 사실값이고, 검사기가 어휘 소속으로 함께 검사한다.

mistakenIdentity

확장
확정
VarFacts.mistakenIdentity : boolean
근거
IFAB VAR 1.1.d

review_scenario에 값을 추가하지 않았다. 원문은 “when the referee cautions or sends off the wrong player” — 선수 확인 오류는 사건의 종류가 아니라 카드 수여자의 속성이고, 경고와 퇴장 양쪽에서 일어난다. 사건 종류 축에 넣으면 “카드가 제시됐다”와 배타 관계가 되어 버린다.

범주 선택 CARD_SHOWN은 RED_CARD와 MISTAKEN_IDENTITY 양쪽에 걸린다. 판본 규칙에 requiresMistakenIdentity 플래그를 두고 조건이 많은 쪽이 이긴다 — 데이터 줄 순서가 판정을 바꾸지 않게.

send_off_category

확장
확정
DOGSO · SERIOUS_FOUL_PLAY · BITING_OR_SPITTING · VIOLENT_CONDUCT · OFFENSIVE_LANGUAGE_OR_ACTION · SECOND_CAUTION · ENTERING_VOR · NONE
근거
Law 12.3 · 2025/26 p.117

원문 아홉 항목을 판정에 필요한 만큼 묶었다. DOGSO 세 항목(고의 핸드볼 · 자기 진영 밖 비고의 핸드볼 · 프리킥 반칙)은 퇴장 사유로는 하나이고, biting과 spitting은 원문이 한 항목으로 적었다 — 제 계획서가 둘로 나눴던 것이 근거 없는 세분이었다.

소유자 열이 아니라 fact_revisions.facts 안의 값. 8절에 열거형으로 적는다.

var_window_exception

확장
확정
MISTAKEN_IDENTITY · VIOLENT_CONDUCT · BITING_OR_SPITTING · OFFENSIVE_LANGUAGE_OR_ACTION · NONE
8절 초안
MISTAKEN_IDENTITY · VIOLENT_CONDUCT · NONE

작업 중에 새로 나온 일곱 번째다. 원문 VAR 1.10 / Law 5.3은 다섯을 든다 — “mistaken identity or … violent conduct, spitting, biting or extremely offensive, insulting and/or abusive action(s)”. 8절의 두 값으로는 “침 뱉기로 재개 후 퇴장”을 표현할 수 없다.

효과 send_off_category와 값을 맞춰 두어 변환표가 사라졌다. 예외 목록에 걸린 퇴장 사유가 곧 예외 사유다.

값 목록이 비어 있던 열 다섯

채택
observed_card
disciplinary_action 공유
disciplinary_action
NONE · CAUTION · SECOND_CAUTION · SEND_OFF
foul_decision
11절 Decision 5값
goal_decision
observed_goal_decision 공유
restart_type

관측 열과 추천 열이 같은 어휘를 공유한다. 두 벌을 두면 decision_match 비교가 값 변환을 먼저 해야 하고, 그 변환표가 두 어휘가 어긋날 수 있는 자리가 된다.

비대칭은 남긴다 엔진은 어휘의 부분집합만 낸다 — UNKNOWN은 관측 전용이고, SECOND_CAUTION은 이 사건 하나로 알 수 없으므로 관측에서만 들어온다. NONE을 새로 만들지 않고 8절의 PLAY_CONTINUED를 쓴다.

네 게이트

이 스키마가 존재하는 이유. 네 값을 하나로 접으면 “왜 개입하지 않았는가”에 답할 수 없다. 각 게이트는 막았는가와 왜 막았는가를 서로 다른 열에 남긴다.

게이트 1

범주

var_reviewable · var_category

판본이 이 사건 유형을 검토 대상으로 여는가. 대회 채택 옵션은 별개 축이다.

↳ var_not_reviewable_reason
OUTSIDE_REVIEWABLE_CATEGORIES
COMPETITION_OPTION_NOT_ADOPTED
게이트 2

시한

var_within_time_window

창이 아직 열려 있는가. 닫는 유일한 조건은 재개다. 주심이 판정을 내렸다는 사실은 전제이지 차단 조건이 아니다.

↳ var_window_closed_reason PLAY_RESTARTED
↳ var_window_exception ≠ NONE 이면 재개해도 열림
게이트 3

문턱

var_threshold_met

명백한 오심인가. 불리언이 아니다 — 강도가 속도 게이트에 걸리면 UNDETERMINED가 정직한 값이다.

↳ MET · NOT_MET · UNDETERMINED
게이트 4

절차

var_review_procedure

개입한다면 어느 절차인가. 사실적·주관적 구분에서만 나오며 문턱과 무관하다.

↳ OFR (주관적) · VAR_ONLY (사실적) · NONE

동시에 성립해야 하는 상태 — var_reviewable = true 이면서 var_intervention = NO_INTERVENTION. 검토 대상이지만 문턱을 넘지 않아 개입하지 않은 경우다. 이 둘을 한 값으로 합치면 “검토 대상이 아니었다”와 “검토했지만 개입할 정도가 아니었다”가 같은 문장이 된다. 픽스처 var-19가 이걸 검사한다.

review_scenario는 중계에서 관측한 판정 상황이지 VAR 범주가 아니다. 범주로 가는 매핑은 판본 데이터에 있다 — SECOND_CAUTION이 2025/26 에선 어디에도 닿지 않고 2026/27 에선 RED_CARD에 닿는 것이 그 매핑의 전부다.

코드에 매핑을 두면 판본 교체가 코드 수정이 된다.

enum review_scenario {
  GOAL_DISALLOWED
  GOAL_AWARDED

  PENALTY_GIVEN
  SENDING_OFF_NOT_GIVEN
  CARD_SHOWN
  SECOND_CAUTION
  CORNER_KICK_AWARDED
  OTHER [note: '버리는 값이 아님. 엔진이 OUT_OF_SCOPE 를 반환하는 입구']
}

enum camera_sufficiency { LOW MEDIUM HIGH }
enum playback_speed { NORMAL SLOW UNKNOWN }
enum severity {
  CARELESS        [note: '징계 없음']
  RECKLESS        [note: '경고']
  EXCESSIVE_FORCE [note: '퇴장']
}

// VAR 네 게이트 — 합치지 않는다
enum var_category {
  GOAL_NO_GOAL
  PENALTY_NO_PENALTY
  RED_CARD
  MISTAKEN_IDENTITY
  CORNER_KICK [note: '2026/27 신설 + competition option']
  NONE
}
enum var_threshold_result {
  MET
  NOT_MET
  UNDETERMINED [note: '불리언이 아닌 이유: 강도가 속도 게이트에 걸리면 이 값이 정직하다']
}
enum var_intervention { NO_INTERVENTION OVERTURNED CONFIRMED }
enum var_no_intervention_reason {
  NOT_REVIEWABLE    [note: '범주 게이트']
  TOO_LATE          [note: '시한 게이트']
  THRESHOLD_NOT_MET [note: '문턱 게이트']
}
enum var_not_reviewable_reason {
  OUTSIDE_REVIEWABLE_CATEGORIES  [note: '판본에 그 범주가 없음']
  COMPETITION_OPTION_NOT_ADOPTED [note: '판본엔 있으나 대회가 채택 안 함']
}
enum var_window_closed_reason {
  PLAY_RESTARTED [note: '검토 창을 닫는 유일한 조건. 원심 선언은 차단 조건이 아니다']
}
// IFAB VAR 1.10 / Law 5.3 원문이 다섯을 든다. README 8절 초안의 두 값으로는
// "침 뱉기로 재개 후 퇴장"을 표현할 수 없어 원문이 나눈 만큼으로 넓혔다.
enum var_window_exception {
  MISTAKEN_IDENTITY
  VIOLENT_CONDUCT
  BITING_OR_SPITTING
  OFFENSIVE_LANGUAGE_OR_ACTION
  NONE
}

// IFAB Law 12.3 「Sending-off offences」 2025/26 p.117 아홉 항목을 묶은 것.
// DOGSO 세 항목은 퇴장 사유로는 하나. biting/spitting은 원문이 한 항목.
// 열이 아니라 fact_revisions.facts 안의 값이다.
enum send_off_category {
  DOGSO
  SERIOUS_FOUL_PLAY
  BITING_OR_SPITTING
  VIOLENT_CONDUCT
  OFFENSIVE_LANGUAGE_OR_ACTION
  SECOND_CAUTION
  ENTERING_VOR
  NONE [note: '퇴장 사안이 아님']
}

// observed_card 와 disciplinary_action 이 함께 쓴다.
// 엔진은 SECOND_CAUTION 을 내지 않는다 — 이 사건 하나로는 알 수 없다.
enum disciplinary_action { NONE CAUTION SECOND_CAUTION SEND_OFF }

enum foul_decision { FOUL NO_FOUL NORMAL_CONTACT INCONCLUSIVE OUT_OF_SCOPE }
enum var_review_procedure {
  OFR      [note: '주관적 판정']
  VAR_ONLY [note: '사실적 판정']
  NONE
}
enum inconclusive_reason {
  CAMERA_INSUFFICIENT   [note: '각도 부족']
  SEVERITY_UNDETERMINED [note: '강도 특정 불가']
  SLOW_MOTION_ONLY      [note: '정상 속도 관측 없음 — 속도 게이트']
  OUT_OF_SCOPE          [note: '규정에 조문 없음. 영상이 부족한 게 아니다']
}

// facts JSONB 안의 값 — 열이 아니지만 게이트가 읽는다
enum referee_decision_type {
  NO_FOUL
  FOUL_AGAINST_ATTACKER
  FOUL_AGAINST_DEFENDER
  PLAY_ON
  UNKNOWN [note: '이 값이 UNKNOWN 이 아니라는 사실이 VAR 검토의 전제']
}
enum decision_nature { FACTUAL SUBJECTIVE }
enum error_magnitude { CLEAR_AND_OBVIOUS NOT_CLEAR_AND_OBVIOUS UNDETERMINED }
enum contact_type { PUSHING CHARGING HANDBALL TACKLE OTHER }
// 불리언 두 개도 facts 안에 있다 — 열거형이 아니지만 게이트가 읽는다
//   mistaken_identity       주심이 다른 선수에게 카드를 줬는가 (VAR 1.1.d)
//                           → MISTAKEN_IDENTITY 범주와 재개 후 예외의 입구
//   serious_missed_incident 주심단이 사건 자체를 보지 못했는가
//                           → 문턱 게이트가 error_magnitude 와 OR 로 읽는다

// ── 재현 체인 ───────────────────────────────────────

Table incident_candidates {
  id uuid [pk]
  analysis_id uuid [not null]
  candidate_index integer [not null]
  review_scenario review_scenario [not null]
  start_ms integer [not null]
  end_ms integer [not null]
  broadcast_clock varchar
  detection_confidence real
  camera_sufficiency camera_sufficiency [not null]
  current_fact_revision_id uuid
  review_status varchar [not null]
  created_at timestamptz [not null]
}

Table fact_revisions {
  id uuid [pk]
  incident_candidate_id uuid [not null]
  revision integer [not null]
  facts jsonb [not null]
  fact_schema_version integer [not null]
  source varchar [not null]
  extraction_confidence real
  model_version varchar
  created_at timestamptz [not null]

  indexes { (incident_candidate_id, revision) [unique] }
}

Table decision_results {
  id uuid [pk]
  analysis_id uuid [not null]
  incident_candidate_id uuid [not null]
  fact_revision_id uuid [not null]
  applied_rule_version_id uuid [not null]

  observed_restart_type varchar [not null]
  observed_restart_beneficiary varchar [not null]
  observed_card disciplinary_action
  observed_goal_decision varchar [not null]
  observed_source varchar        [not null]

  // 관측 열과 같은 어휘를 쓴다. 두 벌을 두면 decision_match 비교가
  // 값 변환을 먼저 해야 하고, 그 변환표가 어긋날 수 있는 자리가 된다.
  foul_decision foul_decision
  severity severity
  goal_decision observed_goal_decision
  restart_type observed_restart_type
  disciplinary_action disciplinary_action

  decision_match varchar [not null]

  var_reviewable boolean [not null]
  var_category var_category [not null]
  var_within_time_window boolean [not null]
  var_threshold_met var_threshold_result [not null]
  var_intervention var_intervention [not null]
  var_no_intervention_reason var_no_intervention_reason
  var_not_reviewable_reason var_not_reviewable_reason
  var_window_closed_reason var_window_closed_reason
  var_window_exception var_window_exception [not null]
  var_review_procedure var_review_procedure [not null]

  judgment_confidence_level varchar [not null]
  inconclusive_reason inconclusive_reason
  fact_signature bytea [not null]
  rule_engine_version varchar [not null]
  evaluation_schema_version integer [not null]
  evaluation_snapshot jsonb [not null]

  citations jsonb [not null, note: 'CHECK jsonb_array_length(citations) >= 1']
  cited_laws "text[]" [note: 'GENERATED ALWAYS AS (...) STORED']
  created_at timestamptz [not null, note: '갱신 시각은 두지 않는다']

  indexes {
    (incident_candidate_id, fact_revision_id, applied_rule_version_id, rule_engine_version) [unique]
    (fact_signature, applied_rule_version_id, rule_engine_version)
  }
}

Table rules {
  id uuid [pk]
  authority varchar [not null]
  edition varchar [not null]
  law varchar [not null]
  section varchar [not null]
  concept varchar [not null]
  revision integer [not null]
  content_sha256 bytea [not null]
  original_text text
  official_korean text [note: 'KFA 대조판 확보 전까지 비워 둔다']
  plain_korean text
  source_page varchar
  source_url text
  review_status varchar [not null]
}

Table competition_rule_versions {
  id uuid [pk]
  competition varchar [not null]
  season varchar [not null]
  effective_from date [not null]
  effective_to date
  ifab_edition varchar [not null]
  source_document text
  verification_status varchar [not null, note: '현재 INFERRED']
}
